# Methodology

Audit date November 21, 2026. Scope covers the new English-language Post-Build Technical Educator article and library-wide technical discovery. The primary reader action is copying a reusable prompt. The canonical origin is https://prompts.robertdevore.com.

The delivery chain starts with Markdown front matter, the verbatim prompt source, and Howl assets. Kujo SSG and Python postprocessors create static HTML, discovery surfaces, and optimized media. GitHub Pages builds on main using checksum-verified Kujo 1.0.1, and Cloudflare serves the custom domain. Howl renders independently using the installed CLI. The repository names its own generated output and freezes its public route structure.

The untouched baseline is the GitHub Pages deployment artifact for dbdb6d4, run 44942848128. Verify its sealed archive with the checksum in raw/baseline-output.sha256. The archive is ignored locally and can also be downloaded from the linked run while retained by GitHub. Baseline site contract and the downloaded build's tracked source are independently recorded. Baseline receipts precede edits. The external and production probes start from public HTTP, independently of the artifact.

The collector reconciles the sitemap with self-canonical generated directory routes. It parses main text, head markup, image dimensions, schema, and links. It compares sampled production response status, canonical, and main content with the pinned artifact. Reported indexability is technical eligibility for the audited routes. The contact route's main-text difference comes from Cloudflare email obfuscation. Generated-output validators check canonical consistency, discovery records, and internal asset and route links. Counts are link occurrences unless noted. 401, 403, 405, and 429 responses are indeterminate for external links. Crawl depth is shortest distance from the home page.

For reproduction from the repository root, extract the matching Pages artifact and set SEO_AUDIT_OUTPUT to its directory, then run collect_audit.py, collect_production.py, and collect_weights.py with --phase after from this workspace's scripts. Use a fresh dated workspace for new baselines. The Playwright test accepts SITE_BASE, AUDIT_PHASE, and PLAYWRIGHT_MODULE. Lighthouse 13.0.1 uses mobile defaults, headless Chrome, and the same live URL before and after. The lab result is a single measured sample per phase. Static weights are uncompressed generated references and exclude remote fonts, dynamic requests, and caching. Browser measurements show interaction and rendering at the tested widths. Internal SEO and AI-readiness scores were omitted because coverage of visibility inputs is incomplete.
